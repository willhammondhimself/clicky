# Lumen Skins and Precise Pointing Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace upstream's blue-triangle identity with three switchable skins (Ember, Instrument, Marginalia; default Marginalia with Ember's motion), draw pointing marks around the real on-screen element found through Accessibility, and strip upstream's first-run experience.

**Architecture:** Pure, harness-tested units decide everything that can be decided without AppKit: the skin catalog and its tokens, which visual state the companion shows, coordinate conversions, element-rect selection, companion parking and bubble text. A thin Accessibility wrapper feeds the selection rules off the main actor. SwiftUI views per skin render companion, mark and bubble; the overlay and the panel read the selected skin from `AppSettings` and switch live.

**Tech Stack:** Swift 5 mode, SwiftUI + AppKit (macOS 14.2 target, macOS 26 glass when available), ApplicationServices Accessibility API, Swift Testing via the `LumenLogic` SwiftPM harness.

**Spec:** `docs/superpowers/specs/2026-10-19-skins-design.md` (visual reference: the "Lumen look board" artifact, cards A/B/C).

## Global Constraints

- Never run `xcodebuild`. Verify with `tools/typecheck.sh` (expect `typecheck: 0 errors`) and `cd tools/logic-tests && swift test`. Will runs Cmd+R / Cmd+U.
- Known flaky test: `KokoroTTSClientTests.aCancelledReplyDoesNotMarkTheNextReplyAsFinished` may fail on a loaded machine; every other test must pass.
- New pure files: Foundation/CoreGraphics only, `nonisolated`, symlinked into `tools/logic-tests/Sources/LumenLogic/` with tests in `leanring-buddyTests/` symlinked into `tools/logic-tests/Tests/LumenLogicTests/` (relative target `../../../../leanring-buddy/<File>.swift`). Delete `tools/logic-tests/.build` once after adding symlinks. Tests use the `#if canImport(leanring_buddy) … #else @testable import LumenLogic #endif` header.
- Naming: clarity over concision, no single-letter names (AGENTS.md). Do not rename the `leanring-buddy` directory, scheme or module. Do not fix the known Swift 6 / onChange warnings.
- Default actor isolation is MainActor. Accessibility calls must not run on the main actor.
- No new network calls, permissions, bundled fonts or cloud models. Fonts are system designs only: `.serif` (New York), `.monospaced` (SF Mono), `.rounded` (SF Pro Rounded).
- Skin palettes are fixed per skin; skins do not follow macOS light/dark mode and never sample screen pixels. Legibility comes from each skin's halo.
- Skin switching is live, never restarts, and never joins `bindSettingsObservation`'s `.dropFirst(7)` merge.
- The `[POINT]` grammar and the `MemoryTagParser`-before-`parsePointingCoordinates` order stay unchanged.
- Commits: conventional (`feat:`, `fix:`, `docs:`, `chore:`), no AI attribution lines.

## Review Focus

1. The Accessibility hit is Lumen's own overlay or panel window → treated as a miss, fallback box drawn (Task 3 test `ownProcessHitFallsBackToBox`).
2. A display left of or above the primary display (negative global coordinates) → conversions round-trip and the mark lands on the right element (Task 3 test `conversionsRoundTripOnDisplayLeftOfAndAbovePrimary`).
3. A target at a screen edge or corner → the parked companion stays fully on screen (Task 3 test `parkingFlipsToStayOnScreenAtEveryCorner`).
4. A tiny hit (a text run inside a button) whose parents are all huge containers → the tiny element is used, not the fallback box (Task 3 test `tinyHitWithOnlyHugeParentsKeepsTheTinyElement`).
5. The model sends `[POINT:x,y:none]`, an empty label or whitespace → the bubble falls back to a short phrase, never "none" (Task 3 test `noneOrBlankLabelUsesAPhrase`).

### Task 3: Pointing geometry, element-rect selection and bubble text

**Files:**
- Create: `leanring-buddy/PointingGeometry.swift`, `leanring-buddy/ElementBoundsSelection.swift`, `leanring-buddy/PointingBubbleText.swift`
- Test: `leanring-buddyTests/PointingGeometryTests.swift`, `leanring-buddyTests/ElementBoundsSelectionTests.swift`, `leanring-buddyTests/PointingBubbleTextTests.swift` (+ symlinks)

**Interfaces:**
- Produces:
  - `nonisolated enum PointingGeometry`:
    - `static func accessibilityPoint(fromAppKitGlobalPoint appKitGlobalPoint: CGPoint, primaryScreenHeight: CGFloat) -> CGPoint` (y = primaryScreenHeight − y).
    - `static func appKitGlobalRect(fromAccessibilityPosition accessibilityPosition: CGPoint, size: CGSize, primaryScreenHeight: CGFloat) -> CGRect` (origin.y = primaryScreenHeight − position.y − height).
    - `static func overlayLocalRect(fromAppKitGlobalRect appKitGlobalRect: CGRect, screenFrame: CGRect) -> CGRect` (SwiftUI top-left space of that screen's overlay: x − screen.minX, screen.maxY − rect.maxY).
    - `static func companionParkingPoint(forTargetRectInOverlay targetRect: CGRect, overlaySize: CGSize, companionRadius: CGFloat, gap: CGFloat) -> CGPoint` — default spot is just outside the bottom-left corner (`targetRect.minX − gap − companionRadius`, `targetRect.maxY + gap + companionRadius`); flip horizontally to the right side when it would leave the screen on the left, vertically above when it would leave at the bottom; finally clamp to `[companionRadius, size − companionRadius]`.
  - `nonisolated struct AccessibilityElementCandidate: Equatable { let role: String?; let frameInAppKitGlobal: CGRect; let processIdentifier: Int32 }` — ordered from the hit element up through its ancestors.
  - `nonisolated enum TargetRectSource: Equatable { case accessibilityElement, fallbackBox }` and `nonisolated struct TargetRectResolution: Equatable { let rectInAppKitGlobal: CGRect; let source: TargetRectSource }`.
  - `nonisolated enum ElementBoundsSelection` with constants `containerRoles: Set<String> = ["AXWindow", "AXScrollArea", "AXWebArea", "AXSplitGroup", "AXLayoutArea", "AXApplication", "AXBrowser"]`, `maximumAreaFractionOfDisplay = 0.25`, `minimumElementWidth = 12`, `minimumElementHeight = 10`, `fallbackBoxSize = CGSize(width: 44, height: 28)`, and `static func resolve(candidatesFromHitUpward: [AccessibilityElementCandidate], appKitGlobalPoint: CGPoint, displayFrame: CGRect, ownProcessIdentifier: Int32) -> TargetRectResolution`.
    Rules, in order: empty list → fallback. Hit from `ownProcessIdentifier` → fallback. A candidate is *unusable* if its role is in `containerRoles`, its area exceeds 25 % of the display, or its frame is empty. Starting from the hit: if the hit is unusable → fallback; if the hit is smaller than the minimum size, walk up to the first usable ancestor that meets the minimum size, stopping at the first unusable ancestor and keeping the last usable one seen (so a tiny element with only huge parents is kept). The chosen rect is clipped to `displayFrame`; an empty clip → fallback. The fallback box is `fallbackBoxSize` centred on the point, clipped to the display.
  - `nonisolated enum PointingBubbleText`: `static let fallbackPhrases = ["right here", "this one", "over here", "here it is"]` and `static func bubbleText(elementLabel: String?, fallbackPhraseIndex: Int) -> String` — trimmed label when non-empty and not case-insensitively `"none"`, else `fallbackPhrases[fallbackPhraseIndex % count]`.
