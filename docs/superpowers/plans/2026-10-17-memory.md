# Lumen memory: profile + daily notes + "remember this" / "forget"

## Context

Lumen (fork at `~/code/lumen`, branch `feature/direct-providers`, Kokoro TTS merged 2026-10-15) answers screen-aware voice questions but forgets everything on quit and knows nothing about Will. The agreed roadmap (docs/HANDOFF.md) names **memory** as the next feature, modelled on HeyClicky's PROFILE.md/VOLATILE.md injected into the system prompt. Grilled decisions (2026-10-17, all confirmed by Will):

- Markdown under `~/Library/Application Support/Lumen/Memory/`: `PROFILE.md` + `notes/YYYY-MM-DD.md` + `notes/index.json`. Memory **on by default**. Starter profile prefilled from what we know about Will.
- Writes: model emits `[REMEMBER:Section:fact]` (stripped before TTS, appended under that heading; unknown → Notes); transcript fallback when the question starts with "remember that/this/to …" and the model emitted no tag; `[FORGET:text]` removes the most similar profile line (embedding cosine ≥ 0.7) and the spoken reply gets "forgot: …" appended (or "i couldn't find that in my memory."). Every exchange → one daily-note line summarised by **`gemma4:e2b`** (background, text-only); raw `question → first sentence` entry when the summariser isn't available.
- Reads: profile always whole; today's note whole; top 8 past entries by **`embeddinggemma`** cosine ≥ 0.5 against the question; whole block capped at 8,000 chars (≈2k tokens), drop oldest first. Sent to whichever chat provider is active (no cloud toggle). Model may recall naturally, never reads memory out unprompted, never mentions having a memory file.
- Models auto-pulled from Ollama at launch when missing (`/api/pull`, status row like Kokoro's). Until ready / Ollama unreachable: inject profile + last two days whole, raw daily entries, Retry button.
- Panel: Memory toggle, "Open memory folder", profile line count, "Forget today" (deletes today's note + its index entries), status row. Visual layout deferred to a choice board.
- Unchanged: in-run 10-turn conversation history; screenshots/screen text never stored.

Verified against the machine: Ollama 0.34.4 running; `/api/tags` returns `models[].name` + `capabilities` (includes `"embedding"` for embedding models); `/api/generate` with `stream:false, think:false` works; `/api/embed` refused on the chat runner ("start it with --embeddings") — expected, embeddinggemma gets its own runner. `gemma4:e2b` ≈ 4.6 GB, `embeddinggemma` 622 MB (768-dim, 2k ctx). Installed now: gemma4:26b (26B-a4b MoE), qwen3.6:35b, llama3, deepseek-r1:32b.

## Architecture

Pure Foundation-only units (harness-tested via `tools/logic-tests`) + one `actor` for file I/O + one `@MainActor` `MemoryManager` singleton that `CompanionManager` and the panel talk to. Memory enters the prompt by appending to the existing static system prompt at its single call site (`CompanionManager.swift:633`); both chat clients pass `systemPrompt` verbatim, so no `ChatClient` change. Memory tags are stripped **before** `parsePointingCoordinates` (its regex at `CompanionManager.swift:803` is end-anchored).

**System prompt additions** (appended only when memory is on), verbatim:
```
memory:
you have a long-term memory about the user. it appears below under "what you know about the user" and "recent notes". use it to be personal and specific and recall things naturally when they're relevant, the way a friend would. never read your memory out unprompted, never list what you know, and never mention that you have a memory file, notes, or a profile. if they ask what you remember about something, answer from memory in your own words.

saving memories: when the user tells you something worth keeping (a fact about them, a project, a tool they use, a preference, or anything they say "remember that…" about), add a tag to your reply: [REMEMBER:Section:fact] where Section is one of About me, Projects, Tools, Preferences, Notes and fact is one short sentence about the user in third person. the tag is removed before your reply is spoken, so also acknowledge it in words. one tag per fact; several tags are fine. don't save things you only see on screen unless the user asked you to remember them, and never save passwords, keys, or other secrets.

forgetting: when the user asks you to forget something, add [FORGET:text] where text is the fact as closely as you remember it. the app removes the matching line and will add what was forgotten to your reply, so don't describe what you forgot yourself.

put memory tags right before the point tag, at the end of your reply.

examples:
- user: "remember that my cat is called mochi" → "mochi, great name. noted. [REMEMBER:About me:has a cat called mochi] [POINT:none]"
- user: "i've switched from vscode to zed by the way" → "nice, zed's quick. i'll keep that in mind. [REMEMBER:Tools:uses zed as their editor, switched from vscode] [POINT:none]"
- user: "remember to ship the demo on friday" → "on it. [REMEMBER:Notes:wants to ship the demo on friday] [POINT:none]"
- user: "forget what i said about the cat" → "sure, dropping that. [FORGET:has a cat called mochi] [POINT:none]"
- user: "what's my cat called again?" → "mochi, unless there's been a rename. [POINT:none]"
```
Dynamic block: `what you know about the user:` + profile text; `recent notes (oldest first; today's are complete, earlier ones were picked for this question):` (fallback header: `recent notes (today and yesterday):`) + lines `YYYY-MM-DD HH:MM · App · summary`.

**Summariser call**: `/api/generate` `{model:"gemma4:e2b", system, prompt, stream:false, think:false, keep_alive:-1, options:{temperature:0.1, num_predict:60}}`. **Embed**: `/api/embed` `{model:"embeddinggemma", input:[…], keep_alive:-1}` → `embeddings`. **Pull**: `/api/pull` `{model, name, stream:true}` NDJSON `{status,total,completed}` → fraction (per-layer, clamped), `{status:"success"}` / `{error}`.

## Rulings made during execution

- **Similarity thresholds lowered** (retrieval 0.5 → 0.3, FORGET 0.7 → 0.4): measured against the real `embeddinggemma` on 2026-10-17 with the EmbeddingGemma task prefixes (`task: search result | query: ` / `title: none | text: `). Relevant note lines score ≈0.45–0.5 and unrelated ≤0.2; FORGET paraphrases 0.45–0.6 and absent facts ≤0.25. The planned numbers would have missed most real matches. Cost if wrong: an occasional loosely related note line in the prompt, or a FORGET removing a neighbouring fact (the removed line is spoken back and logged to today's note).
- **Raw-fallback first sentence** uses its own splitter, not `SentenceSplitter`, because the latter merges sentences under 20 characters for speech pacing.
- **`ollama pull`** of both models was run from the terminal during implementation (exactly what the app does at first launch) so the endpoints could be probed; Will's first Cmd+R will therefore skip the download.

## Final review (fresh reviewer, 2026-10-17) and fix pass

No Critical. Fixed (each with a test that failed first where the harness reaches it; suite 119/119):
- Interrupting during TTS synthesis swallowed `CancellationError` in the inner TTS catch, spoke the error voice and logged an unheard reply → rethrown; `recordExchange` also gated on `!Task.isCancelled`.
- Bare "remember …" questions were stored as facts → only "remember that/this/to", never when the transcript ends with "?".
- `[FORGET]` embedding call had no timeout → wrapped in the 5 s retrieval timeout; substring fallback prefers the longest match.
- A pull stream ending without `success` counted as installed → client throws on EOF; provisioner re-lists after pulls before `.ready`.
- A timed-out index rebuild discarded all work → index saved per file.
- `[REMEMBER:meeting at 10:30]` split on the time's colon → the first segment is a section only when it names a known heading; newlines inside facts/forgets become spaces.
- App names containing the separator or empty made unparseable note lines → sanitised.
- `.ollamaUnreachable` was sticky for the whole session (launch-at-login before Ollama) → re-checked after 30 s, also from the retrieval path.

Deferred minors (not fixed): interrupted-mid-generation chat errors arrive as `URLError`, so the pre-existing error voice still plays and the transcript fallback may store a fact the user then repeats; `memoryPromptBlockTask` isn't cancelled when the screenshot throws; nested brackets or `[REMEMBER]` without a colon pass through to speech; a hand-edited bullet with extra spaces after the dash can't be removed by FORGET; "Forget today" during an in-flight `recordExchange` briefly re-adds the file (self-heals); history includes the app-appended "forgot: …"; memory instructions are appended even when the block is nil; the new Toggle styling differs from the "Show Lumen" toggle; `profileFactLineCount` only refreshes on app writes; `kokoroStatusText` reused for memory rows; the planned launch-time self-test log line for `OllamaNativeClient` was not added (the endpoints were probed from the terminal instead).

Rulings on the reviewer's set-aside items: thresholds were calibrated on the real model (above); "Forget today" stays a single button; a dictated secret can reach the daily note (README now says so); summariser GPU contention on back-to-back questions is accepted; exchanges whose TTS failed are still logged.
